# Corona DR — визуализация «как Corona» и сетевой рендер для Blender

Аддон (extension) для Blender 4.2+ (проверен на **Blender 5.1.1 и 5.2.3 LTS**, macOS).
Два независимых блока, оба — в **Properties → Render**:

1. **Corona (визуализация)** — режим «как Corona Render» поверх Cycles.
2. **Сетевой рендер (DR)** — распределённый рендер одной сцены по локальной сети
   (аналог Corona DR). Работает **с любой сценой**: с режимом Corona, с обычными
   настройками Cycles и собственным компоновщиком, а также с EEVEE.

**Скачать:** [corona_dr-1.1.0.zip](https://github.com/volik1987/corona-dr/releases/latest/download/corona_dr-1.1.0.zip)
(страница релизов — [Releases](https://github.com/volik1987/corona-dr/releases)).
В репозитории файл собирается в `dist/` командой `./build.sh`.

## Установка

Blender → Edit → Preferences → Get Extensions → ⌄ (вверху справа) → **Install from Disk…** →
выбрать `corona_dr-1.1.0.zip`. Или из терминала:

```bash
/Applications/Blender.app/Contents/MacOS/Blender --command extension install-file -r user_default -e dist/corona_dr-1.1.0.zip
```

Аддон ставится на **каждый** компьютер, который будет рендерить (или узел запускается без
интерфейса — см. ниже). Версии Blender на узлах лучше держать одинаковыми.

## 1. Режим Corona

Галочка в заголовке панели **«Corona (визуализация)»** перенастраивает Cycles:

| Corona | Что делает аддон в Cycles |
|---|---|
| Лимит проходов / времени / шума | `samples` (0 = без лимита), `time_limit`, адаптивный сэмплинг с порогом = шум % / 100 |
| Пресеты | Черновик (64 прохода, 5%), Средне (3%), Финал (2%), Высокое (1%) |
| Денойз | Intel OIDN с albedo + normal, «Accurate». При включённом VFB денойз делается в компоновщике — есть «Сила денойза» (смешивание с шумным) |
| «Физичные» умолчания | 25 отскоков, без каустик, Max sample intensity 20 (clamp indirect), light tree, фильтр 1.5 px, path guiding по желанию (CPU) |

**VFB: постобработка** — цепочка узлов в компоновщике (Blender 5 — node group «Corona VFB»):
экспозиция (EV) → баланс белого в Кельвинах + tint (Color Balance «White Point») → сжатие
светов `c/(1+c·(1−1/HC))` → контраст → насыщенность → Bloom → Glare (лучи) → виньетка →
резкость. Тонмаппинг — AgX / Filmic / PBR Neutral / Standard (view transform сцены).
Цепочка живёт в компоновщике, поэтому после рендера правки видны сразу, без перерендера.
«VFB во вьюпорте» включает компоновщик в 3D-виде (вид из камеры).
Прежний компоновщик сцены не теряется: при выключении VFB он возвращается.

**LightMix** — кнопка «Создать LightMix» заводит light group на каждый источник и на окружение;
в списке у каждой группы вкл/выкл, цвет и сила. Группы денойзятся по отдельности и
складываются в компоновщике — можно менять свет после рендера. Светящиеся материалы
без light group в LightMix не попадают (назначьте им группу в Object → Shading).

**Материалы и свет:**
- *Материал Corona Physical* — группа узлов поверх Principled BSDF с параметрами по-Corona:
  цвет, шероховатость, металл, уровень отражения, IOR, преломление, просвечиваемость,
  непрозрачность, покрытие (clearcoat), sheen, тонкая плёнка, свечение, нормаль.
- *Corona Light* — Area-источник, цвет по температуре (K), мощность, размер, «видим в камере».
  «Температура выделенным» — задать Кельвины уже существующим лампам.
- *Corona Sun + Sky* — лампа Sun + физическое небо (Multiple Scattering / Nishita).
  Небо само следует за поворотом солнца.

## 2. Сетевой рендер

### Узлы

На каждом рендер-компьютере: панель «Сетевой рендер (DR)» → **«Включить узел рендера»**.
Узел — фоновый TCP-сервер (порт 19400) внутри Blender; сам рендер идёт в отдельном
процессе `blender -b`, поэтому интерфейс не блокируется. В настройках аддона: имя, порт,
**общий ключ сети** (узел примет задания только с тем же ключом), число потоков, папка кэша,
автозапуск узла вместе с Blender.

**Предпросмотр на узле** — галочка «Показывать готовые части на узле» (в панели под кнопкой
узла и в настройках аддона, включена по умолчанию). Сам рендер идёт в фоне без окна, но после
каждой готовой части кадра или кадра анимации узел показывает её в Image Editor как
изображение «Corona DR узел» (если редактора нет — один раз откроется отдельное окно).
Если этот же компьютер — головной и идёт его задание, картинка только обновляется и не
перебивает показ итога.

Узел без интерфейса (ферма, другой Mac/ПК без монитора):

```bash
blender -b --factory-startup --python <путь к аддону>/node_cli.py -- --port 19400 --name ПК-2
```

(`node_cli.py` лежит внутри установленного аддона и в `corona_dr/` этого репозитория;
параметры `--cache`, `--threads`, `--key`.)

### Головной компьютер

1. **«Найти узлы»** — поиск по UDP (порт 19401, широковещание + мультикаст). Если узел в
   другой подсети — добавьте его вручную по IP и порту.
2. В таблице у узла: вкл/выкл, вес (производительность), ручной диапазон кадров, состояние,
   прогресс и число готовых заданий.
3. «Головной тоже рендерит» — на этом компьютере автоматически поднимется свой узел.
4. Выберите режим и нажмите **«Сетевой рендер»**. Сцена сохраняется копией (ваш файл не
   меняется), ресурсы упаковываются (pack resources) и отправляются узлам (повторно — только
   если сцена изменилась).

**Режим «Кадр»** — кадр режется на части (сетка или полосы, `render.use_border` +
`use_crop_to_border`), узлы рендерят их в многослойный EXR со всеми проходами (в т. ч.
Denoising Albedo/Normal и light groups). Головной склеивает части и **один раз** делает
денойз и постобработку на целом кадре — поэтому швов нет. Постобработка:
- «Как в сцене» — Corona VFB, если включён режим Corona, иначе компоновщик сцены;
- «Компоновщик сцены» — обычный рендер: ваш компоновщик (Render Layers подменяется
  собранным EXR) и денойз, если он включён в Cycles;
- «Без постобработки» — только сборка и денойз.

Итог сохраняется в «Папку кадра» (формат — из Output сцены) и открывается в Image Editor
как изображение «Corona DR». Собранный сырой EXR остаётся во временной папке задания.
Частей лучше брать в 2–4 раза больше, чем узлов. Лимит времени Corona действует на каждую часть.

**Режим «Анимация»** — кадры распределяются между узлами:
- *Очередь* — свободный узел берёт следующий кадр;
- *По весам* — непрерывные куски пропорционально весу узла;
- *Вручную* — диапазоны в столбце «Кадры» (например `1-50` на ПК-1, `51-100` на ПК-2;
  можно `1-10, 20, 30-40`). Кнопка «Заполнить диапазоны по весам» расписывает их автоматически.
  Неназначенные кадры уходят в общую очередь.
- «Кадров за раз» — сколько кадров узел рендерит за один запуск Blender;
- «Свободные узлы помогают» — освободившийся узел забирает кадры из конца чужой очереди.

Кадры собираются на головном по пути Output сцены (видео-формат заменяется на PNG-кадры).

**Надёжность:** если узел упал или пропала связь, его текущее задание и вся его очередь
переотправляются другим узлам; задание, упавшее на узле, повторяется на другом
(до 3 попыток). Узел, который молчит 2 минуты, считается упавшим.

### Ограничения

- Внешние кэши (симуляции, Alembic, VDB-последовательности) не упаковываются в .blend —
  на узлах они должны лежать по тем же абсолютным путям.
- В режиме «Кадр» с EEVEE экранные эффекты (bloom/AO в самом EEVEE) считаются по частям
  и могут дать стыки; для EEVEE надёжнее режим «Анимация».
- Узлы принимают сцены от любого компьютера сети — задайте общий ключ, если сеть не доверенная.
  Скрипты внутри .blend на узлах не выполняются (`-Y`).
- Проверено на Blender 5.1.1 и 5.2.3 LTS; для 4.2–4.5 есть ветки совместимости (Composite-узел,
  старые свойства узлов), но они не тестировались.

## Тесты

```bash
./tests/run_tests.sh
```

Собирает zip, ставит его в **чистый временный профиль** Blender и проверяет:
- `tests/test_addon.py` — режим Corona, VFB, материалы/свет, LightMix, локальный рендер,
  сетевой рендер через операторы аддона: «Кадр» с Corona VFB, «Кадр» обычным рендером
  (совпадает с локальным рендером), «Анимация» в Cycles и EEVEE, «Кадр» в EEVEE;
- `tests/test_dr.py` — два узла на портах 19410/19411: UDP-поиск; кадр по 6 частям —
  размер совпадает с цельным рендером, сырой Combined совпадает попиксельно, на швах нет
  скачков; анимация 1–4 по ручным диапазонам (A: 1–2, B: 3–4); переотправка кадров
  мёртвого узла.

Снимок панелей: `blender <сцена.blend> --python tests/ui_shot.py -- снимок.png`.

## Устройство

```
corona_dr/                  исходник аддона (это и есть extension)
  blender_manifest.toml
  __init__.py               регистрация, настройки аддона
  props.py                  свойства сцены (scene.corona, scene.corona_dr)
  corona.py                 Cycles-пресеты, Corona Physical, свет, Sun+Sky, LightMix
  vfb.py                    цепочка VFB в компоновщике (без bpy-аддона — нужна и post.py)
  corona_ops.py, dr_ops.py  операторы; dr_ops — задание головного, таймер прогресса
  ui.py                     панели
  node_cli.py               узел без интерфейса
  dr/protocol.py            TCP-кадры «JSON + данные», UDP-поиск
  dr/node.py                сервер узла, запуск blender -b, прогресс по «Sample N/M»
  dr/master.py              планировщик: части, очереди, веса, ручные диапазоны, переотправка
  dr/node_render.py         рендер части/кадров внутри blender -b
  dr/post.py                склейка EXR (OpenImageIO), денойз и VFB на целом кадре
build.sh                    сборка zip в dist/
tests/                      автотесты
```
